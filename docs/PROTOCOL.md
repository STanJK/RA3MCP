# 输入管道协议 v1

端点：`\\.\pipe\RA3MCP.<游戏 PID>`。Windows 本机字节模式命名管道，拒绝远程客户端，同一时刻一个连接。每次请求固定 24 字节，响应固定 24 字节，所有多字节整数为小端。流式读取必须循环直到收满整帧，不依赖一次 Read/Write 对应一个消息。

## 请求

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | u32 | magic `0x504D3352`，字节 `52 33 4D 50`，ASCII `R3MP` |
| 4 | u16 | version `1` |
| 6 | u8 | operation |
| 7 | u8 | button：0 左键、1 右键、2 中键 |
| 8 | u32 | sequence，响应原样返回 |
| 12 | i32 | x，客户区像素 |
| 16 | i32 | y，客户区像素 |
| 20 | i32 | value，滚轮刻度；其他操作填 0 |

| operation | 含义 | 使用字段 |
| --- | --- | --- |
| 0 | Ping | sequence |
| 1 | Move | x、y |
| 2 | Down | button、x、y |
| 3 | Up | button、x、y |
| 4 | Wheel | x、y、value，范围 -100..-1 或 1..100 |
| 5 | ReleaseAll | 释放桥接模块记录为按下的键 |

坐标先检查在 0..65535，再由游戏线程检查 `x < 客户区宽度`、`y < 客户区高度`。重复 Down 和未由桥接模块按下的 Up 会被拒绝，避免释放用户自己的按键；实体输入和合成输入仍可能在游戏内部互相影响。

## 响应

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | u32 | 同请求 magic |
| 4 | u16 | version `1` |
| 6 | u8 | status |
| 7 | u8 | held mask：bit0 左、bit1 右、bit2 中，仅记录桥接模块状态 |
| 8 | u32 | sequence |
| 12 | u32 | pump counter，32 位回绕 |
| 16 | u32 | detail |
| 20 | u32 | 保留，固定 0 |

| status | 含义 | detail |
| --- | --- | --- |
| 0 | Pumped | 0；在原输入循环返回后回执 |
| 1 | Invalid | 0 协议格式、2 越出客户区、3 重复 Down、4 无对应 Down 的 Up |
| 2 | NotReady | 1 窗口未就绪；事件对象创建失败时为 Win32 error |
| 3 | Busy | 队列已满 |
| 4 | Timeout | 1 尚在队列且已取消；2 可能已开始执行；系统等待失败时为 Win32 error |

Invalid 协议格式、Busy 和事件创建失败可以由管道线程立即回复；坐标/按键状态检查及正常指令在游戏线程执行。等待 3 秒仍未完成就超时。Timeout/detail 中的 Win32 error 与 1/2 可能数值重合，不能把 detail 当作可靠的可重试标志；任何 Timeout 都停止当前动作。

## 执行与生命周期

管道工作线程只校验、入队和等待，不直接调用游戏函数。输入循环 hook 在调用原函数前，从至多 64 项的队列取出至多 32 项，将输入送入游戏已有鼠标队列；原输入循环随后消费它们。游戏线程不会等待队列锁，也不读写管道或日志。

控制器每发一条请求就等待回执，再发下一条，因此一次点击的 Move/Down/Up 和拖动的移动采样分别经过输入循环。多个请求如果由其他客户端实现流水发送，则不保证每条请求占据不同帧；v1 控制器禁止流水发送。

`Pumped` 表示原输入循环已返回，不表示游戏玩法/UI 接受了动作。连接断开请求下次输入循环释放桥接模块按键；它不是同步的断线回执。连接中的空闲时间没有自动松键，拖动可以跨帧保持按下。不同 CLI 进程之间不保留按键状态，因此 CLI 不提供单独的 Down/Up；长期连接可用 Rust `Session` API。

超时前尚未取出的请求被标为取消，随后弹出时不会执行。已经开始执行的请求无法回滚，桥接模块请求下次输入循环释放按键。不要自动重发非幂等的点击/拖动。原生鼠标输入继续运行；首版没有隔离物理输入或后台输入策略。

## 固定测试向量

Wheel，sequence=`0x12345678`，坐标 `(800,600)`，value=`-2`：

```text
52 33 4D 50 01 00 04 00 78 56 34 12 20 03 00 00 58 02 00 00 FE FF FF FF
```

C++ 和 Rust 测试都使用这一独立向量固定字段位置、符号和字节序。测试脚本仅在用户本机运行。
